# GUI 技术路线调研

## 当前建议

采用 Qt 6 Widgets 实现传统桌面窗口，以 C++17 编写 GUI；通过自有 C 适配层调用固定版本 PuTTY 的 C99 密钥核心，并使用 CMake 构建。该路线已写入 `design.md`，已获用户批准；本机 Qt 6.12 开发构建已通过，两个 Ubuntu 的 Qt 6.8.3 兼容构建进行中。本研究中的建议以最终设计为准。

理由：原版是单窗口、菜单与模态对话框为主的工具，Qt Widgets 能直接表达这些交互；复用原版核心有助于保留全部算法、证书和格式兼容。Qt 与上游核心在源码层分离，避免把 GUI 控件传入密码模块。

备选方案包括包装命令行程序或用其他密码库重新实现。前者难以完整复现 Windows GUI 的内存状态、鼠标熵输入、证书交互与实时进度，后者增加文件格式和旧算法兼容的验证负担，因此优先研究直接复用核心。

## 上游复用依据与接口边界

- `CMakeLists.txt:50` 定义 `keygen` 目标并加入格式导入实现；`windows/puttygen.c:585` 通过核心函数处理 RSA、DSA、ECDSA 与 EdDSA 生成。
- `windows/puttygen.c:2029` 检查两次口令是否一致；格式已在前序分支选择。`:2079` 检查保存参数，`:2089` 调用 PPK 保存实现。实现前应再次核对精确分支。
- 上游头文件和数据结构应仅暴露在 C 适配模块中，GUI 通过不透明句柄和自有参数类型调用；错误信息与进度通过受控边界返回。
- 状态至少区分无密钥、收集熵、任务处理中和密钥已加载；证书和格式是否适用另用能力信息表示，避免菜单和主窗的逻辑分叉。
- 单窗口只允许一个密码任务运行，适配层负责持有和清理密钥对象；原版全局随机状态的初始化、线程访问与释放规则仍需研究。
- 保留鼠标收集熵的操作，同时明确调用系统随机源并复用上游随机实现；不能把界面进度等同于已验证的密码安全性。
- 敏感数据不通过命令行参数、日志或持久临时文件传递；口令生命周期与敏感缓冲区清理需在设计中说明。

## 实施前待解决的技术项

1. 固定公开可获取的 Qt 补丁版、PuTTY 0.85 来源与构建工具；验证 C/C++ 适配层和平台随机/文件接口所需的最小依赖集合。
2. 逐项核查上游 GUI 与资源对话框，补齐功能清单；所有 G01–G15 的测试或人工验收方式写入实施计划。
3. 推荐 Windows ZIP 便携包和 Ubuntu 对应版本的 DEB 包；构建与打包应固定工具和依赖版本。具体交付形式列入最终方案审阅。
4. Linux 使用相容的 X11/Wayland 插件并在两种桌面会话中验证文件对话框、鼠标熵事件和剪贴板；尚未实测。
5. 帮助采用本地可访问内容，关于窗口包含上游版本与许可信息。用户已确认中英双语、默认中文；设计包含语言切换与偏好记忆。
6. 从 Qt 实际发行包确认模块许可和部署要求，随产物保留 Qt 与 PuTTY 所需材料；未进行法律判断。

## 补充调研

- [Qt 6.8.3 公开源码归档](https://download.qt.io/archive/qt/6.8/6.8.3/submodules/)可访问，作为初始可复现兼容构建基线；最终发布补丁版本在实施阶段核查并锁定。
- 本机通过 `pkg-config` 查询 Qt Core/Widgets/Test 均为 6.12.0；只能用于开发测试，不能据此宣称已经验证 6.8 兼容构建。
- [Qt 国际化说明](https://doc.qt.io/qt-6.8/internationalization.html)和 [QTranslator](https://doc.qt.io/qt-6.8/qtranslator.html) 提供翻译资源机制；设计使用英文源文本、中文资源和默认中文，不根据操作系统语言改变首次默认值。
- [Qt Widgets 许可说明](https://doc.qt.io/qt-6.8/qtwidgets-index.html#licenses)列出其发行许可。设计采用动态链接，发布材料按实际使用模块核查；上游 PuTTY 许可原文保留。
- `ssh.h:1500`、`:1504` 提供 PPK/SSH-1 内存加载，`:1536` 提供 PPK 内存保存，`:1669`、`:1673` 提供外部格式内存导入；`:1675`、`:1677` 为文件导出接口。设计不假定所有外部格式都有直接的内存导出 API。
- `windows/puttygen.c:1217`、`:1308` 的证书添加与移除实现使用匹配后的核心密钥重建，GUI 应复现相应判断，不能仅把证书文件路径存成字段。

本调研不表示构建、打包或跨平台验收已经完成。

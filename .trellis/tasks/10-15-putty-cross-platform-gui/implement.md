## 拟定验证命令

以下命令对应尚待实现的工程和测试目标，不是已执行的验证结果。Windows 在相应 MSVC 工具链环境执行等效命令；所有生成目录位于工作目录 `.tmp/`。

```bash
cmake -S . -B .tmp/build/debug -G Ninja -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build .tmp/build/debug --parallel
ctest --test-dir .tmp/build/debug --output-on-failure -L core
ctest --test-dir .tmp/build/debug --output-on-failure -L interop
ctest --test-dir .tmp/build/debug --output-on-failure -L gui
cmake -S . -B .tmp/build/release -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF
cmake --build .tmp/build/release --parallel
cmake --install .tmp/build/release --prefix .tmp/package-root
cpack --config .tmp/build/release/CPackConfig.cmake -B .tmp/packages
```

测试运行的临时目录和配置根显式重定向到 `.tmp/`。无真实显示时使用离屏 Qt 插件执行逻辑测试；它不替代 X11/Wayland 和 Windows 桌面实测。测试标签、打包配置和依赖前缀在工程建立时落实。

## 质量门与回退点

- 每阶段运行与改动对应的检查；最后由 `trellis-check` 结合 G01–G15、AC1–AC11 做全范围审查，不用重复镜像实现的测试充数。
- 高风险文件为上游构建适配、C 句柄所有权、随机初始化、跨线程生命周期、证书合并、保存格式和 Qt 发布依赖。各自完成后保留可审阅的改动点。
- 核心契约变更时同步 GUI 调用和测试；翻译变更时检查全部菜单、对话框及资源收集；Qt 或上游变更时重复互操作与兼容构建。
- 上游与 GUI 目录分离，便于回退适配；不得为通过检查删除原版高级或旧算法功能。
- 规范模板只有在代码落地后按真实文件/模式补充，保留中文约束；不将本设计文档作为已经存在的编码惯例。
- 完成后按 Trellis 检查、规范更新与收尾流程记录证据；任何未验证的平台/功能都保留未完成状态。规划阶段不提交、归档或运行产品构建。

# PuTTY 套件技术设计

## 状态与基线

本设计已获用户最终批准并进入实施阶段，不是现有代码说明。用户已确认 PRD 中的六组件、平台、Qt/CLI 和原版功能范围。固定 PuTTY 0.85、现有 Qt 6.8.3 发布工具链及 C99/C++17，不在本任务顺便升级依赖。源码依据见 research/，实现必须验证下述技术门。

## 组件与目录边界

| 拟定路径 | 职责 |
| --- | --- |
| apps/putty/ | Qt 主程序的 C 适配、会话控制器、配置桥、终端控件、资源、测试与安装内容 |
| apps/pageant/ | Qt 代理入口、密钥管理、原生 IPC 适配、生命周期、资源及测试 |
| apps/plink/、apps/pscp/、apps/psftp/ | 各 CLI 目标入口、安装及程序特有测试；不复制上游解析器 |
| libs/putty-runtime/ | 两个新 Qt 程序实际共用的 C 核心边界、平台事件桥和 Qt 运行时；不包含终端或密钥管理产品 UI |
| cmake/SuitePuTTY.cmake、cmake/SuiteCLI.cmake | 完整 Qt 核心前缀目标和独立 CLI 上游配置 |
| cmake/SuitePackaging.cmake、tools/suite/ | 套件唯一打包入口、受控服务夹具、报告及平台集成工具 |
| apps/puttygen/、cmake/UpstreamPuTTY.cmake | 继续负责现有密钥工具；只做必要构建/安装集成 |

新共享目录只容纳这次确有两个调用方的代码。既有 pg_* 接口保持专用，不强制重写为通用套件接口。第三方源仍统一在 vendor/putty/；必要补丁留 vendor/patches/，补充来源与差异。

## 构建隔离与组件选择

保留现有 PUTTY_BUILD_PUTTYGEN 默认开启；新增 PUTTY_BUILD_PUTTY、PUTTY_BUILD_PAGEANT、PUTTY_BUILD_PLINK、PUTTY_BUILD_PSCP、PUTTY_BUILD_PSFTP，初期默认关闭以保留现有构建。全部启用由明确的套件配置指定。仅新 GUI 查找 Qt，共享 Qt 运行时只在需要时加入；CLI-only 和全部关闭不依赖 Qt。

CLI 从原版根独立配置和生成，以 ExternalProject 或等价隔离方案构建选中的三个原目标；显式声明构建依赖、产物和安装目标，不执行上游全量安装。不下载另一份上游、不覆盖 CMAKE_SOURCE_DIR、不全局污染编译选项。使用相同编译器/架构/构建类型，Windows 资源、运行库和实际产物路径纳入验证。

Qt 客户端使用 suite-* 前缀目标和独立生成配置头，复用固定源文件但不链接 pg-putty。保留原版断言与所需计时、网络、GSSAPI、SSH 共享连接、串口、代理及 X11 能力；不继承密钥工具 NO_GSSAPI/NOT_X_WINDOWS/no-timing 的裁剪。X11 桌面窗口能力和 SSH X11 转发分别验证；Wayland 桌面不意味着禁止连接本机可用的 Xwayland/X server。

## C 边界、线程与消息契约

每个新 GUI 进程只有一个 PuTTY 核心所有者线程和一个运行时，统一持有 PRNG、callback/timing 队列、平台网络、Conf 及其所有子对象。不要把各连接放入任意并行 QThread。CLI 保留原版事件循环；PuTTYgen 保留其现有进程内工作线程契约，互不共享核心内存。

C 适配持有上游结构和 vtable，向 Qt 控件仅暴露自有不透明句柄、类型化请求及公开状态，不在 QWidget 里 include 上游结构并修改字段。外部文本区分 UTF-8、上游 STR/STR_AMBI、Filename/FontSpec 与原版协议字节，禁止统一盲转 UTF-8。敏感输入按请求复制、用后安全清除，不进入状态投影或日志。

所有 GUI→核心命令包含运行时/会话代次、命令类型和自有参数，按队列串行执行；核心→GUI 的帧、状态、控件更新和用户请求包含同样的代次及单调序号。带回调请求另有 request_id，响应只提交一次；失效、取消、断开和关闭均明确失败/取消，不默认为接受。队列有界，帧可合并，业务命令不能静默丢弃；背压保留最终屏幕、输入和退出顺序。

共享事件桥在核心线程工作：Unix 按上游 uxsel 的读写及异常顺序接 QSocketNotifier；Windows 优先复用 WSAAsyncSelect 隐藏 HWND→原版响应/回调链，并接入 HANDLE 等待集，不能把 Windows socket/HANDLE 当 Unix fd。顶层回调按预算调度，不无界 drain；计时绝对 tick 转为单次定时器，处理重入、回绕和取消。

关闭采用两阶段清理：先进入 closing、停止新外部输入与业务请求，拒绝在途用户请求；再在核心线程释放 Ldisc/Backend/Terminal 等对象并执行其内部清理。核心析构仍可能产生新回调，因此最后再次清扫宿主上下文的顶层回调、桥消息和排队 Qt 事件，撤销剩余通知并使宿主代次失效，之后才释放宿主。不能只在析构前删除一次回调。socket 关闭/复用仍保持原版 moribund 过滤；异步请求宿主在安全收尾前保持存活。

## 终端渲染与输入

复用上游 Terminal、Ldisc 和 Backend 解释终端状态，不以 QTextEdit 或外部 Plink 文本替代终端。TermWin 的字宽和绘制是同步回调，不能在核心线程阻塞等待 GUI。

首选核心线程持有私有字体度量及 QImage 绘制设备；遇到任意 Unicode 字符可本地计算度量，缓存按字体、回退、DPI/DPR 和渲染代次区分，不能只预缓存常用字符。完整绘制批次完成后发布不可变帧，GUI paintEvent 只呈现；核心后续绘制使用分离缓冲，禁止双方同时修改同一图像。字体/DPI 改变触发新代次和全量重画，丢增量帧时以完整帧恢复。

GUI 负责 QWidget、IME、系统剪贴板、窗口操作、可访问性及原生对话框，向核心提交键盘/预编辑提交、鼠标、滚轮、尺寸、焦点、粘贴和配置事件。特殊键与应用键盘模式走上游格式化逻辑。TermWin、Seat 同步查询读取核心拥有的值镜像；远端窗口/尺寸请求异步回执并完成上游 resize 回调，不能悬挂。

保留真实的 Seat 信任状态和 TermWin 信任标记，认证提示与远端输出可区分。异步主机密钥、弱算法和日志覆盖确认支持拒绝/取消；远端主通道退出与连接断开分开处理，转发仍存活时不提前释放后端。

## 配置、存储与双语

以 Conf 及原版 config/dialog 描述为配置业务模型，将全部 dlg_* 控件和事件映射到 Qt。核心保有控制值、上下文、item id 和焦点镜像；GUI 变更先进入核心镜像，再调用上游 handler；程序刷新抑制伪用户事件，动态列表以 id 而非翻译文本识别。平台原生特有描述分别适配，不能只用通用 config.c 声称已覆盖所有功能。

编辑使用独立 Conf 草稿，取消不改运行会话，确认走原版预重配置/日志/Ldisc/终端/Backend 顺序。保留同平台原版 settings.c 与 storage.c：Windows HKCU 原路径，Linux 原版目录/环境覆盖。GUI 和 CLI 的会话、主机密钥/CA 相互可读；字体保存使用原版 FontSpec 格式，不用 QFont.toString 取代。非当前页面字段必须保留；对原版本身不保留的未知字段不扩大承诺。存储错误不能被 GUI 报为成功。

GUI 偏好可单独使用 QSettings，不替代原版会话存储。默认中文、英文切换及偏好记忆沿用 PuTTYgen 的用户行为。翻译只涉及操作文字；协议标识、指纹、会话名、远端内容与脚本输出不翻译。语言切换更新控件标签，保留连接、密钥、请求及未提交编辑。

## Pageant 原生接口与入口

复用 pageant.c/pageant.h 的密钥、证书、延迟解密和请求核心，不自建简化签名协议。公开列表用协议版本及公钥 blob 标识身份，不能把默认指纹当唯一键；裸公钥与多个证书可共享私钥。错误口令、取消、删除时在途签名和重加密按原版状态处理，不复活已删除条目；批量临时口令用后清除。

Windows 保留命名管道、单实例命名互斥，以及 FindWindow("Pageant","Pageant")/共享映射/WM_COPYDATA 旧接口，使用隐藏兼容窗口并校验对端权限。原版与 Qt Pageant 任意先启动时均按原语义复用已有代理；GUI 不偷偷启动不兼容的第二服务。保留显式 --openssh-config、--unix、-c 等原参数；WSL 1 按原版适用性验收，WSL 2 不承诺额外桥接。

旧 WM_COPYDATA 的同步窗口/等待者在独立 IPC 辅助线程，由事件交接给唯一核心线程处理；不能在核心 WndProc 中等待同一核心队列的签名回复。退出时先令在途请求失败并唤醒等待者，再撤销 IPC 资源。网络 HWND 与旧 IPC HWND 分开管理，辅助 IPC 线程不拥有或并发访问核心密钥。

Linux 保留 pageant 的原命令行、多实例、SSH_AUTH_SOCK 和生命周期语义；不把 Windows 单实例强加到 Unix。桌面入口调用同一程序新增的 pageant --gui，原来无参数行为及显式 CLI 模式不变，不新增另一个组件。GUI 提供可复制的 socket/环境启动信息，不自动改用户 shell 配置；--openssh-config 等显式用户操作保留其原定行为。纯 Wayland 支持 Qt 口令提示，但 -X 仍表示原版 X11 生命周期。

Linux 原 CLI 模式在 QApplication/核心工作线程创建前分流，保持无图形环境可用，不在启动 Qt 或多线程后调用原版 fork 路径。已安装 GUI 在合法且权限验证通过的用户 XDG_RUNTIME_DIR 下创建私有代理目录，不依赖源码仓库，也不自动退回宽权限目录；原 CLI 生产模式保留其原目录/生命周期。开发与原版对照测试必须先通过可注入前缀或记录过的最小测试适配，将这些运行目录全部覆盖至项目 .tmp/，否则禁止运行。

有托盘时关闭列表隐藏并保留托盘管理；无托盘时不隐藏成不可控后台进程，关闭窗口提供“保持运行/退出”，保持运行后必须留有可见控制入口。窗口菜单始终包含完整操作与退出。有待处理请求时退出先令请求失败，再撤销监听和敏感状态。

## 性能、取消与验证门

共享基础先建立线程归属/事件/队列契约；终端子任务第一步必须在 Windows 和 Linux 完成网络、同步 TermWin 度量/绘制、高 DPI/字体回退、长 KDF/GSSAPI 的纵切验证，然后才铺开完整配置 UI。Pageant 同样验证在途口令与代理请求的串行和退出。

计划的自动验证指标：窗口 GUI 心跳间隔 50ms，在受控持续输出及高成本 KDF 下，连续 10 秒采样最大停顿不超过 250ms；停顿统计同时保存负载/平台数据，作为内部工程验证阈值。输入与帧队列监测高水位且不无限增长，恢复后最终屏幕与服务端数据一致。该阈值是实现验证标准，不改变用户功能范围；若环境噪声造成失败，先诊断，不擅自放宽。

关闭采用异步状态机：GUI 立即进入可见的关闭/取消中状态，不 join 正在执行同步 KDF/GSS 的核心，也不强杀 QThread。同步调用返回后在安全点清理，禁止提前释放状态。原生 GSS 等阻塞调用不承诺硬性取消时限；如线程方案在任一目标系统不成立，优先研究隔离核心子进程或可审计异步补丁并回到设计评审，不能删功能或转为长期阻塞 GUI。

## 验证隔离与兼容证据

原版客户端/代理、适用 OpenSSH 和受控 SSH/SFTP/转发/串口对端提供独立证据。Linux PUTTYDIR、随机种子、代理 socket、运行时与配置均指向项目 .tmp/；上游 Pageant 默认系统临时路径必须先覆盖再运行。Windows 使用专用测试身份，或验证过的进程级临时注册表 hive 覆盖，不写用户 HKCU。不修改 HOME 等系统常见变量；代理环境只在测试子进程中清理/替换。隔离探针须逐个核对原版/自有子进程实际使用的 HKCU、随机种子、配置、socket/管道、运行时与日志根；RegOverridePredefKey 不被假定自动传给原版子进程，专用身份的开发产物也必须显式重定向到 .tmp/。

对照组为终端 PT-01–PT-22、Pageant P01–P18 与 I01–I14、CLI C01–C05，来源见 research/。每项区分适用平台、正常/失败/取消、证据和未执行状态。平台限制不能被用作隐藏未实现项；SSH-1/旧算法不能因系统 OpenSSH 禁用就删除，可用固定上游和独立签名对照。

## 套件发布与回退

套件模式使用唯一顶层 CPack 配置，Qt 与许可只收集一份；各组件登记安装内容。Windows ZIP 包含三个 GUI 和三个 CLI 及匹配运行库；双击 GUI 无控制台，CLI 可在控制台使用。Ubuntu 两版各自构建 DEB，安装独立 /opt/putty-suite，启动器指向同包组件；CLI 不无提示覆盖 /usr/bin 已有原版工具。提供明确的套件 CLI 路径及使用说明，Pageant 会话入口调用同包 PuTTY。

保留 PuTTYgen 单组件发布与正在改动的 Arch 系统 Qt 模式。集成前重新核对实时文件，避免旧计划覆盖并行改动。共享部署改动必须验证无 SDK 安装、插件加载、卸载保留配置、包共存和依赖许可；报告定点收集到独立可读目录，不递归上传私有 runtime/socket 树。

按子任务形成可回退改动点。先保留原 PuTTYgen 构建路径；新组件关闭后仍可构建。协议/存储适配失败回退对应新目标，不改用户配置做迁移；构建/包装改动可单独回退，第三方补丁可单独审阅。产品功能若需变更，返回父任务 PRD 与用户评审，不以技术困难自动裁剪。

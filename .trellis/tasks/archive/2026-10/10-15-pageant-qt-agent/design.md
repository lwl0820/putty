# Pageant Qt 密钥代理设计

## 基线与契约

共同设计以 ../10-15-putty-suite-completion/design.md 为准：构建隔离、唯一核心线程、类型化 C 边界、代次/请求、原版存储、测试身份隔离和独立部署。该文档及本设计共同组成可评审方案；不是已实现能力。

## 责任与数据流

按父设计复用代理核心和原生传输，在同一核心线程串行运行代理请求与密钥操作。公开身份用协议版本+公钥 blob，保留多证书共享私钥的原模型。Qt GUI 提示通过 request_id/代次关联，在途删除/退出使旧响应失效。Windows 使用兼容隐藏窗口和命名管道，Linux 同程序 --gui 作为桌面入口并展示可复制 socket 信息；CLI 原语义不变。无托盘时始终有可见控制出口。

责任路径（均为拟定实现位置）：apps/pageant/ 的 C 代理适配、Qt 控制器/窗口/托盘、Windows/Unix 原生入口、资源和测试；不得另造简化代理协议。

## 依赖与兼容

Windows 同步 WM_COPYDATA 窗口/等待者使用独立 IPC 辅助线程，将请求交给唯一核心所有者；严禁在核心 WndProc 等待自身核心队列回复，退出时先失败请求并唤醒 IPC 等待者。网络 HWND 与兼容 IPC HWND 分工明确。Linux 原 CLI 在 QApplication/多线程创建前分流，保留无图形环境和 fork 语义。GUI 生产运行目录使用经权限验证的 XDG_RUNTIME_DIR，原 CLI 保留原目录；开发和原版对照必须通过测试适配将所有运行目录覆盖到项目 .tmp/ 后才能启动。

依赖 10-15-putty-suite-foundation 的唯一核心线程、平台桥和隔离夹具。可先以固定原版/协议对端独立验证；I01/I03/I07/I08 最终集成需新 PuTTY 和三个 CLI；托盘新会话入口依赖同包 PuTTY。

固定上游来源/校验、Release 断言和相同平台原版行为保持；GUI 偏好不替代会话存储。所有核心句柄由指定所有者释放，响应和过期事件不能访问旧对象，失败不能投影成成功。工程共用修改前读取实时其它工作，不因本设计覆盖并行改动。

## 验证与回退

Windows 新旧 IPC owner 验证和跨权限、无托盘失控、Unix 原模式被无参 GUI 破坏、延迟口令删除竞态、默认系统临时 socket。先隔离再跑代理；回退新代理不能终止用户原代理。

本任务验收标准和父任务映射见 prd.md，步骤与命令见 implement.md。原生平台、真实桌面及未执行项分别记录；没有对应环境时保留缺口，不把静态研究作为通过。涉及产品范围变更时先更新父规划并重新评审。

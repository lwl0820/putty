# 受控 Windows SSH 测试对端独立审查

日期：2026-10-15。仅审查 `tools/suite/windows/ssh_peer.py` 与 `ssh_peer_tests/`；本次直接修复局部夹具问题，没有修改产品、上游、公共运行器或工作流。任务仍处于 Windows 终端纵切阶段。

## 已修复的发现

### 连接总期限没有覆盖命令执行和阻塞等待

原实现只在握手／等待命令的循环核对 25 秒期限，命令执行重新从零计时；通道发送或密钥重协商等待期间也没有独立执行期限的路径。

修复：连接创建时冻结单调时钟截止点，命令、退出状态和最终输出等待沿用该截止点。现有监听线程每轮检查过期连接，先关闭底层 socket 再停止传输，从而唤醒命令线程中的 I/O 等待；达到总连接上限后停止接受连接，但仍执行既有连接的期限检查。未新增计时线程，检查粒度至多约 100ms。命令因期限失败时不记录为完成。

真实回归覆盖正常执行中的连接期限、模拟下游阻塞期间真实 socket 被独立关闭，以及监听达到总连接上限后继续断开过期连接。后两项分别使用可释放的等待和缩短的固定限额，避免依赖 25 秒长等待或永不返回的测试线程。

### 未完成密钥交换后留下统计外的 Timer

固定 Paramiko 5.0.0 的 `Packetizer.start_handshake` 会启动 `threading.Timer`，而其 `close` 不取消未完成握手的 Timer。原夹具只统计监听／工作／传输线程，因而可能报告 `live_threads=0`，实际仍有 Timer 存活。

修复：现有 packetizer 子类直接以单调时钟实现公开的握手期限方法，不创建 Timer。回归通过真实明文 banner 进入 KEX、确认已收到服务器 KEX 数据，然后关闭对端；除核对统计，还比较实际进程中新出现的 Timer，防止统计本身漏报。失败清理会取消旧实现遗留的 Timer，避免污染后续用例。

### SSH 通道接收限额只是客户端通告

固定 Paramiko 的通道数据处理直接向缓冲添加数据，不在该路径把通告的窗口或单包大小作为硬限制。应用层 4097 字节检查在消费时才执行，未消费的输入扩展数据也没有界限。

修复：在 packetizer 的消息返回点、进入 Channel 缓冲之前拒绝全部入站 extended-data，核对标准输入消息的实际长度，并强制单包不超过 32KiB、整连接通道输入累计不超过 64KiB。应用消费上限仍为 4096 字节加一个超额探测字节。固定命令只需要 22／642 字节，无需开放扩展数据。回归发送真实 SSH 扩展数据，以及故意越过客户端窗口节流的加密单包／多包消息，确认服务端会断开。

## 其它已核对边界

- `check_auth_publickey` 只准许固定用户和 key blob；签名仍经过固定库的真实 `verify_ssh_sig`。已有“正确公钥声明、另一私钥签名”的真实回归通过，不能仅凭公钥探测统计认定认证成功。
- 两条 exec 只作为精确字节标记分支；没有 shell、子进程、文件或个人配置读取路径。PTY、shell、subsystem、环境、X11、代理／TCP 转发及其它全局请求均拒绝；每连接只允许一个 session。
- 监听仅 `127.0.0.1` 动态端口；最多 2 个活动工作连接、16 次接受，无无限历史。明文 banner 与原始 SSH 读取限额保留；主机私钥只在内存。
- 退出先关闭底层 socket，线程共享 3 秒 join 预算，超时明确报错；重复关闭、握手中关闭、负载中关闭均有真实覆盖。
- Linux 原版 CLI 对照入口明确拒绝 Windows；使用既有逐进程 `IsolationEnvironment`，报告仅允许项目 `.tmp/`，逐层拒绝符号链接并独占创建 0600 文件。它不证明未经隔离的 Windows CLI 可运行。

本次没有更改产品契约或公共接口；现有产品规范无需因测试夹具新增协议约束而扩展。夹具的具体资源契约及失败回归在本记录和源文件保留，主会话如建立统一测试对端规范可引用本记录。

# 构建与发布

## 范围和证据

目标为 Windows 10（1809+）/11 x64、Ubuntu 22.04/24.04 x64。兼容构建使用 Qt 6.8.3 动态库；Windows 使用 MSVC 2022，两个 Ubuntu 版本分别使用 GCC 11 与 GCC 13。实际通过的构建、自动化检查与人工验收必须单独记录；仓库包含 CI 配置，不表示 CI 已经运行或 Windows 10/11 已完成实测。

本机较新的 Qt 可供开发。发布模式 `PUTTYGEN_RELEASE_PACKAGING=ON` 强制检查锁定的 Qt 版本、x64 架构、系统及源码/许可材料，避免误把开发机器产物当正式发布。Qt 补丁升级时先更新 `tools/qt/qt-sources.json` 并重新跑三平台构建和原生验收。

所有构建、下载、缓存、测试配置与安装暂存均放在项目 `.tmp/`。下文在仓库根目录执行；不在系统临时目录创建工作文件。

顶层项目为 PuTTY 套件，`PUTTY_BUILD_PUTTYGEN` 默认开启。组件源码、测试、资源和发布配置位于 `apps/puttygen/`；关闭该选项即可配置不依赖 Qt 的套件入口。公共 Qt 工具位于 `tools/qt/`，上游源码位于 `vendor/putty/`。

构建目录中的组件程序位于 `apps/puttygen/src/`，核心测试位于 `apps/puttygen/tests/core/`。CTest 和 CPack 继续使用构建根目录入口：`ctest --test-dir <构建目录>`、`cpack --config <构建目录>/CPackConfig.cmake`。所有测试夹具按构建目录隔离，写入仓库根 `.tmp/tests/`。

## Ubuntu 构建

在对应发行版的专用机器或容器中安装依赖。依赖脚本需要 root，可使用容器；它不属于用户安装流程。

```bash
sh tools/ubuntu-build-dependencies.sh
```

两个 Ubuntu 发布环境统一使用 CMake 3.30.9。构建和打包时使用 `C.UTF-8` locale，确保 CPack 正确处理中文文档和资源文件名；不要以 `LC_ALL=C` 打包。可以将固定版本 CMake 安装到项目专用目录，避免改变系统工具：

```bash
export LC_ALL=C.UTF-8
python3 -m pip install --target .tmp/tools cmake==3.30.9
export PYTHONPATH="$PWD/.tmp/tools"
export PATH="$PWD/.tmp/tools/bin:$PATH"
```

在对应系统分别执行；下面以 22.04 为例，24.04 将目录后缀相应替换：

```bash
python3 tools/qt/build_qt.py --prefix .tmp/qt-ubuntu22.04 --work .tmp/qt-build-ubuntu22.04 --jobs 6
cmake -S . -B .tmp/build/ubuntu22.04 -G Ninja \
  -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DCMAKE_PREFIX_PATH="$PWD/.tmp/qt-ubuntu22.04" \
  -DPUTTYGEN_RELEASE_PACKAGING=ON
cmake --build .tmp/build/ubuntu22.04 --parallel 6
QT_QPA_PLATFORM=offscreen ctest --test-dir .tmp/build/ubuntu22.04 --output-on-failure
cpack --config .tmp/build/ubuntu22.04/CPackConfig.cmake -B .tmp/packages/ubuntu22.04
```

构建脚本直接下载官方归档并与锁定 SHA256 比对。Qt Base、Tools、Translations 和 Wayland 均按该系统编译；缓存归档可在多个构建间复用，先运行一次 `--download-only` 避免并发下载同一文件。默认缓存为 `.tmp/qt-archives/`，网络不可用时也可手动把已下载文件放入此目录，脚本仍执行校验。脚本在构建前设置 `TMP/TEMP/TMPDIR`，防止间接工具使用系统临时目录。

Qt Tools 配置显式禁用 `WrapLibClang` 包发现与 `clang`／`clangcpp` 可选功能，保留 Linguist 翻译工具。仅关闭 `qdoc` 无法阻止配置阶段读取系统 Clang 导出文件；GitHub runner 曾因预装配置引用缺失的 `libclangBasic.a` 而失败。此项目不需要 Clang 解析器，无需补装整套 LLVM 开发库。脚本变更会更新 Actions 的 Qt 缓存键；本地复用构建目录时，建议为新配置使用新的 `.tmp/` 工作目录。

DEB 将应用及 Qt 安装到 `/opt/puttygen-gui/`，提供 `/usr/bin/puttygen-gui`、桌面入口和图标；系统依赖由 `dpkg-shlibdeps` 根据实际 ELF 生成，中文字体由 `fonts-noto-cjk` 提供。包内 Qt 与系统 Qt 分离，不修改原版 PuTTY 配置。卸载保留用户语言偏好，不删除用户密钥。

## Windows 构建

使用 MSVC 2022 x64 Native Tools 环境，准备 Python 3.10 以上、CMake 3.24 以上、Ninja 和 Windows SDK。在 PowerShell 运行：

```powershell
$env:TEMP = "$PWD\.tmp\windows-temp"
$env:TMP = $env:TEMP
$env:PYTHONIOENCODING = "utf-8"
New-Item -ItemType Directory -Force $env:TEMP | Out-Null
python tools/qt/build_qt.py --prefix .tmp/qt-windows --work .tmp/qt-build-windows --jobs 6
cmake -S . -B .tmp/build/windows -G Ninja `
  -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON `
  -DCMAKE_PREFIX_PATH="$PWD/.tmp/qt-windows" -DPUTTYGEN_RELEASE_PACKAGING=ON
cmake --build .tmp/build/windows --parallel 6
$env:PATH = "$PWD/.tmp/qt-windows/bin;$env:PATH"
ctest --test-dir .tmp/build/windows --output-on-failure
cpack --config .tmp/build/windows/CPackConfig.cmake -B .tmp/packages/windows
```

Windows 的 CI 管道和重定向输出可能使用 cp1252，无法表示中文。工作流通过 `PYTHONIOENCODING=utf-8` 设置 Python 标准流，Qt 构建脚本入口也显式采用 UTF-8，保证本地独立执行时中文日志和参数错误能够输出。此设置仅约定 Python 标准流，不改变 MSVC 捕获输出的本机编码解码方式。构建前可运行 `python -B -m unittest discover -s tools/qt/tests -v` 检查此边界，无需下载或编译 Qt。

Windows ZIP 根目录含 `puttygen-gui.exe`、Qt DLL、`plugins/platforms/qwindows.dll` 及应用本地 MSVC 运行库 DLL。Qt 的部署工具收集 Qt 文件，CMake 收集可再发行运行库；不会只放一个需要用户另外安装的 VC 运行库安装器。程序使用 GUI 子系统，双击不会额外弹出控制台。

## 包启动、安装与卸载检查

在没有 Qt SDK 的专用机器验证最终产物，先检查 SHA256 文件及包内容。Windows 示例：

```powershell
python apps/puttygen/packaging/smoke_package.py .tmp/packages/windows/puttygen-gui-0.1.0-windows-x64.zip --platform native
```

Ubuntu 专用验证机器使用与系统版本一致的包，并显式允许安装后卸载：

```bash
python3 apps/puttygen/packaging/smoke_package.py .tmp/packages/ubuntu22.04/puttygen-gui-0.1.0-ubuntu22.04-amd64.deb --install-deb --platform offscreen
```

脚本拒绝覆盖已有应用安装，检查实际动态库解析、桌面入口和卸载文件，报告保存至 `.tmp/package-smoke/`。`offscreen` 只检查启动，不构成桌面验证。在 X11 会话中使用 `--platform xcb`，在 Wayland 会话中使用 `--platform wayland`，再完成下表人工核对。Xvfb 和无窗口的 Weston 可检验平台插件，但不能代替用户桌面的鼠标、剪贴板和文件对话框体验。

| 系统 | 必须记录的检查 |
| --- | --- |
| Windows 10 1809+、Windows 11 | 从 ZIP 双击启动，无控制台；没有 SDK 环境仍可运行；中文和空格路径、剪贴板、高 DPI、键盘导航、退出等待。 |
| Ubuntu 22.04、24.04 的 X11 和 Wayland | DEB 安装、桌面启动、卸载；真实鼠标收集熵、剪贴板、平台文件对话框、中文字体、双语布局、中文和空格路径、高 DPI。 |
| 全平台 | G01–G15、AC1–AC10 对应行为及文件互操作；全部算法、素数策略、证书、PPK/KDF、保存与转换；错误、取消和覆盖确认。 |

记录使用的包名、SHA256、发行版、桌面会话、Qt 和工具链版本，区分编译、逻辑测试、启动检查与人工功能验收。没有证据的行保持未完成。

## 许可与离线重建

发布包 `share/licenses/puttygen-gui/` 保留项目许可证、PuTTY 原版许可证与第三方通知；`Qt/` 中包含完整 Qt `LICENSES`、原始模块源码归档、校验锁、构建脚本与构建信息。归档内部包含 Qt 第三方源码与许可，不能为减小体积只保留顶层许可。

从项目源码重建时，将包内 Qt 归档复制到 `.tmp/qt-archives/`，运行相同构建脚本即可离线复用归档。需要替换 Qt 时使用兼容共享库，重新运行平台和功能检查；应用没有额外施加禁止替换或为调试修改进行逆向工程的限制。完整源码与脚本应随着对应二进制发布保留可获得渠道。

`tools/qt/qt-sources.json` 的 SHA256 在 2026-10-15 依据官方归档的 `.sha256` 或 `.mirrorlist` 核对：[Qt Base](https://download.qt.io/archive/qt/6.8/6.8.3/submodules/qtbase-everywhere-src-6.8.3.tar.xz.sha256)、[Qt Tools](https://download.qt.io/archive/qt/6.8/6.8.3/submodules/qttools-everywhere-src-6.8.3.tar.xz.sha256)、[Qt Wayland](https://download.qt.io/archive/qt/6.8/6.8.3/submodules/qtwayland-everywhere-src-6.8.3.tar.xz.mirrorlist)、[Qt Translations](https://download.qt.io/archive/qt/6.8/6.8.3/submodules/qttranslations-everywhere-src-6.8.3.tar.xz.mirrorlist)。Qt 部署使用官方 [CMake 部署 API](https://doc.qt.io/qt-6.8/cmake-deployment.html)。

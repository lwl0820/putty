# Windows 私钥文件权限契约

## 1. 范围与触发

适用于 `src/core/pg_platform.c` 的 `f_open` 私有写入分支，以及调用该分支的 PPK 和外部私钥格式保存。Windows OpenSSH 会拒绝其他普通用户可访问的私钥；只修测试目录权限无法覆盖产品实际导出行为。

## 2. 接口

```c
FILE *f_open(const Filename *fn, const char *mode, bool is_private);
```

保持上游接口及 `pg_save` 错误契约。新增 Windows 权限 API 依赖只链接到自有适配层及对应测试，不修改第三方密钥算法实现。

## 3. 文件与句柄契约

- Windows 私钥新建与覆盖均使用当前进程用户身份，文件所有者与受保护 DACL 按该身份设置，不继承父目录的普通用户组访问权限。
- 权限设置完成后才能截断和写入。权限失败返回 `NULL`，由保存接口报告 `PG_ERR_IO`；不能静默回退到宽权限保存。
- 使用同一打开句柄设置权限和写入，避免检查路径之后另开文件形成时序间隙。
- 写入前核验句柄上的实际权限；不能仅因设置 API 返回成功就认为 ACL 已持久生效，也不应通过不支持 SMB 的卷信息查询拒绝原本可保存的网络路径。
- Win32 句柄转换为 CRT 文件流时明确所有权转移，失败路径释放尚未转移的资源；文本／二进制模式与 UTF-8 中文、空格路径继续支持。
- 公钥和普通读取保留原来的打开行为。本轮不改变 Linux 文件适配逻辑。

## 4. 校验与错误矩阵

| 情况 | 预期 |
| --- | --- |
| 宽权限父目录中创建私钥 | 文件不继承普通用户组权限，当前用户可读写 |
| 覆盖既有宽权限私钥 | 写入前收紧文件权限，再保存内容 |
| 无法打开或设置私有权限 | 保存失败，既有文件内容保留 |
| 普通公钥保存／文件读取 | 保留原有行为 |

## 5. 正常、基线与错误案例

- 正常：从 GUI 导出 OpenSSH 私钥，原生 `ssh-keygen -y` 可读取，签名与验证仍通过。
- 基线：在继承 `BUILTIN\\Users` 权限的测试目录生成全部算法夹具，互操作测试不额外修正其 ACL。
- 错误：权限设置失败时返回保存错误，不能先截断已有内容或把不安全保存报告为成功。

## 6. 必需验证

Windows 核心回归检查新建、既有宽权限文件覆盖、中文空格路径及失败保留内容，核对实际所有者、DACL 和继承状态。继续使用原生 OpenSSH 的公钥读取、签名与证书互操作测试，不跳过权限检查、不仅在测试里调用 `icacls` 修正产品文件。Linux 核心和互操作回归验证未受影响；MinGW 编译只能作为辅助证据，不能替代 Windows MSVC／OpenSSH 原生运行。

## 7. 错误与正确做法

错误：忽略 `is_private`，直接 `_wfopen`；或在测试里修好 ACL，使失败被隐藏。

正确：在产品私钥打开边界设置受保护权限，失败阻止写入，测试直接验证未经额外处理的导出文件。
